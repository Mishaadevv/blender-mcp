## 🔴 Критический баг: `ops.py` был пустым

Файл `src/blender_mcp/addon/blender_mcp_bridge/ops.py` оказался пустым
(0 байт). Он был восстановлен из истории git того же архива: 890 строк,
реализующих

- `blender_geometry` (~30 bmesh-операций: extrude, bevel, inset, subdivide,
  bridge, spin, merge, recalc normals)
- `blender_modifiers`
- `blender_select_by` (поиск объектов по критерию)
- `blender_undo` / `blender_redo` / `blender_checkpoint`
- `blender_set_context`
- `blender_uv`
- `blender_rig`, `blender_pose`, `blender_physics`
- `blender_scene_ops`
- `blender_render_extras`

В `commands.py` эти инструменты вызывают `_ops.geometry(...)`,
`_ops.select_by(...)` и т.д. Модуль `_ops` — это и есть `ops.py`. Пока файл
был пустым, все 12+ инструментов падали с
`AttributeError: module 'ops' has no attribute 'geometry'`.

Именно это объясняет, почему агент вручную ставил сотни кубиков вместо
Array/Mirror модификаторов: `blender_modifiers` и `blender_geometry` были
физически недоступны, `blender_select_by` и `blender_checkpoint` — тоже.
Не было ни одного способа сделать это правильно и ни страховки на случай
ошибки.

Пустым оказался и `UNIVERSAL_INSTALL.md` (95 строк). Оба файла восстановлены
и сейчас на месте.

Как файлы превратились в пустые — неизвестно (порченное сохранение,
прерванная запись, антивирус, случайная перезапись). Восстановлено из
git-истории, то есть это рабочая версия, а не реконструкция.

> Проверка, что баг не вернулся: `blender_select_by` с любым простым
> фильтром должен вернуть результат без `AttributeError`. Это отдельный
> пункт в `scripts/selftest.py`.

## 🔴 Критический баг: сервер не запускался (4.4.0)

Этот баг был введён в 4.1.0 и сделал весь проект нерабочим.

`server.py` импортировал текст промпта качества так:

```python
from .addon.blender_mcp_bridge.quality_guidelines import QUALITY_SYSTEM_PROMPT
```

Python при этом выполняет `__init__.py` пакета аддона, а он делает
`import bpy`. Вне Blender модуля `bpy` нет, поэтому импорт падал с
`ModuleNotFoundError: No module named 'bpy'` — сервер не стартовал вообще,
а вместе с ним ни один из 122 инструментов. `scripts/mcp_test.py` падал
тоже.

Починён в два слоя, чтобы это не повторилось:

- пакет аддона импортируется без `bpy`, а Blender-специфичные импорты
  уходят внутрь `register()`;
- сервер при неудаче печатает предупреждение и работает дальше без промпта,
  а не падает.

## 🟠 Баг: тихое проглатывание ошибок

В `apply_params()` уже был код сбора неизвестных свойств, но результат
выбрасывался, а предупреждение уходило в `print()` — то есть в консоль
Blender на машине пользователя, куда агент не заглядывает. Итог: если агент
задаёт Array-модификатору свойство с опечаткой
(`realtive_offset_factor` вместо `relative_offset_factor`), модификатор
молча остаётся с настройками по умолчанию, а агент считает, что всё
применилось.

Исправлено в `cmd_add_modifier` и `cmd_set_material_node`: при пропуске
свойства в ответе агенту появляется
`"warning": "These properties were NOT applied: [...]"`.

## 🟠 Баг: `camera_focus` (4.4.0)

```python
cam = str(params.get("camera") or bpy.context.scene.camera.name
          if bpy.context.scene.camera else None)
```

Из-за приоритета операторов это выражение читается как
`str(((camera) or scene.camera.name) if scene.camera else None)`. При
отсутствии камеры `cam` становился строкой `"None"` — она truthy, поэтому
проверка `if not cam` её пропускала, и падение происходило уже внутри поиска
по сцене с невнятным сообщением.

Теперь функция откатывается к активной камере сцены, принимает имя, объект
или `{"name": ...}` и прямо сообщает, какого аргумента не хватает.

## 🟡 Мелочи

- **Дефолтный размер генерируемых текстур — 1024 (1K), не 2048.** Это
  осознанное решение, а не недосмотр: 2K стоит вчетверо дороже по времени и
  памяти, а для большинства задач 1K достаточно. Для 2K нужно явно передать
  `size=2048` в `blender_generate_texture` / `blender_generate_pbr_set`.
  Требование об этом прописано в системный промпт, чтобы агент не забывал.
  Побочный эффект: `bake_texture` тоже defaulted на 1024, это согласовано.
- **`setblocking(True)` в `bridge.py`** — мёртвый код, который сразу
  перекрывался `setblocking(False)` внутри `_Connection.__init__`. Убран.
- **Версии расходились в трёх файлах:** `pyproject.toml` (3.0.0), CHANGELOG
  (4.x) и `bl_info` аддона (1.0.0). Выровнено на 4.4.0.

## 🟢 Системный промпт (`quality_guidelines.py`)

Старый промпт требовал только «рендери с 6 ракурсов и проверяй» — этого
достаточно для одного стула, но не для дома с фасадом. Новый требует:

1. Перед началом большой сборки — проверить, что `blender_select_by`,
   `blender_checkpoint`, `blender_geometry`, `blender_modifiers` реально
   работают, чтобы баг с пустым `ops.py`, если он повторится, был замечен
   сразу, а не привёл к тихому «костылю» из ручных кубиков.
2. Любой повторяющийся элемент фасада (окна, балконы, этажи) — **только**
   через Array/Mirror модификатор с явным шагом смещения, никогда вручную.
3. Жёсткая модульная сетка (например: этаж = 3 м, окно = 1.5 м), заданная
   **до** начала моделирования.
4. Сборка **по стадиям** со скриншотом после каждой (голая коробка → окна
   одной стены → балконы → остальные стены и разрез → интерьер → материалы →
   свет → снег), а не один гигантский batch на весь дом сразу.
5. Явное напоминание про `size=2048` для 2K-текстур.

## Как проверить, что всё починено

Аддон копируется внутрь Blender при установке, поэтому правки в
репозитории недостаточно — аддон нужно переустановить:

```
.venv/Scripts/python -m blender_mcp.setup
```

Затем перезапустить Blender и дождаться `ONLINE` в
3D View > Sidebar (N) > MCP Bridge.

Полная проверка:

```
.venv/Scripts/python scripts/selftest.py    # 142/142
.venv/Scripts/python scripts/mcp_test.py    # 27/27
```
