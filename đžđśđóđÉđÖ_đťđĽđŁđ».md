# Что было не так и что я исправил

## 🔴 Критический баг (главная причина хаоса в хрущёвке)

Файл `src/blender_mcp/addon/blender_mcp_bridge/ops.py` в твоём проекте —
**пустой (0 байт)**. Я сравнил его с историей git внутри твоего же архива
(папка `.git` там была) — в последнем коммите этот файл весит 890 строк
и реализует:

- `blender_geometry` (~30 bmesh-операций: extrude, bevel, inset, subdivide,
  bridge, spin, merge, recalc normals)
- `blender_modifiers`
- `blender_select_by` (поиск объектов по критерию)
- `blender_undo` / `blender_redo` / `blender_checkpoint`
- `blender_set_context`
- `blender_uv`
- `blender_rig`, `blender_pose`, `blender_physics`
- `blender_scene_ops`
- `blender_render_extras`

В `commands.py` эти инструменты просто делают `_ops.geometry(...)`,
`_ops.select_by(...)` и т.д. — а модуль `_ops` (это и есть `ops.py`) **пустой**.
То есть все 12+ инструментов выше при любом вызове падали с
`AttributeError: module 'ops' has no attribute 'geometry'`.

**Это и есть причина того, что агент вручную налепил сотни кубиков вместо
того чтобы использовать Array/Mirror модификаторы** — инструмент
`blender_modifiers` (и общий `blender_geometry`) были физически недоступны,
`blender_select_by` и `blender_checkpoint` тоже, так что не было ни
единого способа сделать это правильно и ни страховки на случай ошибки.

Как файл превратился в пустой — сказать не могу (порченное сохранение,
прерванная запись, антивирус, случайная перезапись агентом — не важно),
но факт восстановлен из твоей же git-истории, так что это 100% рабочая
версия, а не что-то придуманное мной.

**Также пустым оказался `UNIVERSAL_INSTALL.md`** (95 строк → 0) — на работу
не влияет, но раз уж чиню, упоминаю.

## 🟠 Баг №2: тихое проглатывание ошибок

В `apply_params()` (commands.py) уже была логика сбора списка
"неправильных/неизвестных свойств", но она:

```python
apply_params(mod, params.get("properties") or {})   # результат выбрасывается!
```

просто **выбрасывалась**, а предупреждение шло в `print()` — то есть в
консоль самого Blender на компьютере пользователя, куда MCP-агент никогда
не заглядывает. Итог: если агент задаёт Array-модификатору свойство с
опечаткой (`realtive_offset_factor` вместо `relative_offset_factor`,
`count` не тем типом и т.п.) — модификатор молча остаётся с настройками
по умолчанию, а агент думает, что всё применилось.

Я поправил оба места (`cmd_add_modifier` и `cmd_set_material_node`) —
теперь при пропуске свойства в ответе агенту появляется явное поле
`"warning": "These properties were NOT applied: [...]"`.

## 🟡 Мелочи

- Дефолтный размер генерируемых текстур — `1024` (1K), не `2048`.
  Для 2K агенту нужно явно передавать `size=2048` в
  `blender_generate_texture` / `blender_generate_pbr_set`. Я прописал это
  прямо в системный промпт, чтобы агент не забывал.
- В `bridge.py` (`_accept_pending`) есть безобидный, но странный кусок:
  `client.setblocking(True)` сразу перекрывается `setblocking(False)`
  внутри `_Connection.__init__`. Реального вреда нет, просто мёртвый код —
  не трогал, чтобы не плодить лишние правки без надобности.

## 🟢 Новый системный промпт (`quality_guidelines.py`)

Старый промпт требовал только "рендери с 6 ракурсов и проверяй" — этого
достаточно для одного стула, но не для дома с фасадом. Новый явно требует:

1. Перед началом большой сборки — проверить, что `blender_select_by`,
   `blender_checkpoint`, `blender_geometry`, `blender_modifiers` реально
   работают (чтобы баг №1, если он вдруг повторится, был замечен сразу,
   а не привёл к тихому "костылю" из ручных кубиков).
2. Любой повторяющийся элемент фасада (окна, балконы, этажи) — **только**
   через Array/Mirror модификатор с явным шагом смещения, никогда вручную.
3. Жёсткая модульная сетка (например: этаж = 3м, окно = 1.5м), заданная
   ДО начала моделирования.
4. Сборка **по стадиям** со скриншотом после каждой (сначала голая коробка
   → окна одной стены → балконы → остальные стены/разрез → интерьер →
   материалы → свет → снег), а не один гигантский batch на весь дом сразу.
5. Явное напоминание про `size=2048` для 2K-текстур.

## Как применить

1. Останови Blender.
2. В своём проекте (не в этом архиве) замени файлы:
   - `src/blender_mcp/addon/blender_mcp_bridge/ops.py` → взять из этой папки
   - `src/blender_mcp/addon/blender_mcp_bridge/commands.py` → взять из этой папки
   - `src/blender_mcp/addon/blender_mcp_bridge/quality_guidelines.py` → взять из этой папки
3. Переустанови аддон в Blender:
   ```
   .venv/Scripts/python -m blender_mcp.setup
   ```
   (аддон копируется внутрь Blender при установке, поэтому просто
   поправить файлы в репозитории недостаточно — нужно переустановить).
4. Перезапусти Blender, дождись `ONLINE` в 3D View > Sidebar (N) > MCP Bridge.
5. Проверь, что баг реально исчез — попроси агента вызвать
   `blender_select_by` с любым простым фильтром. Если ответ пришёл без
   `AttributeError` — почин точно работает.
